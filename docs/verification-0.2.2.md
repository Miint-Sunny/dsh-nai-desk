# 验证记录：0.2.2

日期：2026-11-17。宿主：dsh 0.2.2-rc.3（桌面端自带的命令行，pnpm 11.28.5）。

## 与 0.2.1 的差异

0.2.2 是第一个使用新包名 `@miint-sunny/dsh-nai-desk` 的版本。0.2.1 及更早的版本发布时用的是旧包名 `dsh-nai5-prompting`。

- 带上 0.2.1 的全部改动：内置技能换成 nai5-prompting v1.2.9。`skills/`、`vendor.json`、`VENDOR.md` 与 `v0.2.1` 标签逐字节相同。
- 带上 0.2.0 之后、尚未推送的 9 个提交：
  - S-002：模型写入一个字段时，只能保留这个字段原有的 `⟪屏蔽N⟫` 占位；
  - chore#102：写入工具的说明改短，不再单独打包 `lib/host.js`、`lib/isolation.js`；
  - chore#106：稿纸界面文字改成书面语；
  - chore#140、chore#143：包名改成 `@miint-sunny/dsh-nai-desk`，打包前自动构建，归档只含运行文件，打包时检查家目录路径和账号名；
  - chore#158：两版 README 的 macOS 安装和反馈说明，加问题反馈模板。
- 另改了版本号、CHANGELOG、README 的安装与升级说明和本记录。
- `lib/` 在合并前后、版本号改动前后重新构建，三个文件的 SHA-256 都和起点一致。

## 合并方式

用 merge，没有 rebase。

- 本机的 9 个提交还没推送，但已经有地方按提交号引用它们：运行中的检出、审查记录，以及从其中一个提交打出的归档。merge 保留这 9 个提交原样，这些对应关系不变；rebase 会把它们换成 9 个新提交。
- 两条线确实分叉了：v0.2.1 从 v0.2.0 往后发，用旧包名；本机这条线已经改名。merge 如实记下这一点。
- 冲突的 5 个文件一次解决，不用在 9 个提交上各解决一遍。
- `origin/main`（v0.2.1）是合并结果的祖先，之后推送是快进，不需要强推。

冲突共 5 个文件，每一边保留自己改的那几行：

| 文件 | 取舍 |
|---|---|
| `package.json`、`package-lock.json` | 包名取本机，版本取 v0.2.1；随后的提交再改成 0.2.2 |
| `CHANGELOG.md` | 本机的 Unreleased 块放在 0.2.1 条目上面；随后改写成 0.2.2 条目 |
| `README.md`、`README.en.md` | 取本机的改写，再带上 v0.2.1 的版本号和验证记录文件名；安装与升级说明随后重写 |

`skills/`、`vendor.json`、`VENDOR.md`、`docs/verification-0.2.1.md` 没有冲突，取自 v0.2.1。`lib/` 没有手工合并，合并后重新构建，内容与合并前一致。

## 临时 DSH_HOME 验收

三个归档：0.2.2 用 `npm pack` 从本记录所在的提交打出（81 个文件；本记录不属于归档）；0.2.1 在临时工作树里检出 `v0.2.1` 标签后打出（118 个文件）；`@miint-sunny/dsh-nai-desk` 0.2.0 从 `2bac2af` 打出（81 个文件，与 11 月 15 日打的那份逐字节相同）。

每个情形都从空的 HOME、TMPDIR 和 DSH_HOME 开始，不复制真实 profile 的任何文件。命令行放在沙箱里运行，沙箱拦住外网和真实 `~/.dsh` 的读写；安装一律带 `--config.offline=true`。桌面端的 `desktop` profile 在空的 DSH_HOME 里建不出来（命令行要求先打开一次桌面端），所以用 `web` profile，和 0.2.0、0.2.1 的验收一致。日常 `~/.dsh` 的桌面端 profile 里 `package.json` 和 `pnpm-lock.yaml` 的 SHA-256 前后相同。

| 情形 | 步骤 | profile 依赖里的 nai 包 | `--dump-config` 里 `nai-desk` 入口 / 「NAI5 提示词」预设 |
|---|---|---|---|
| 从 `@miint-sunny/dsh-nai-desk` 0.2.0 升 | 装 0.2.0，再直接装 0.2.2 | 只有 `@miint-sunny/dsh-nai-desk`，0.2.0 被 0.2.2 替换 | 各 1 次 |
| 从 0.2.1（旧名）升 | 装 `dsh-nai5-prompting` 0.2.1，不卸载，直接装 0.2.2 | 两个包并存：新名 0.2.2 和旧名 0.2.1 | 各 2 次；`--dump-config` 退出 0，没有报错或警告 |
| 同上 | 再卸载旧名 | 只剩新名 0.2.2 | 各 1 次 |
| 按 README 的顺序 | 装 0.2.1，先卸载旧名，再装 0.2.2 | 卸载后没有 nai 包；装完只有新名 0.2.2 | 卸载后各 0 次；装完各 1 次 |
| 全新安装 | 装 0.2.2；再用 README 的命令卸载 | 新名 0.2.2；卸载后没有 | 各 1 次；卸载后各 0 次 |
| 标签方式（本地 git 仓库模拟） | 用 `git+file` 地址安装一个指向本次提交的标签 | 新名 0.2.2 | 各 1 次 |

- 每一步退出码都是 0，每次 `--dump-config` 的标准错误都是空的。
- 从任何一种旧状态走完 README 里的做法，profile 的依赖里都只有一个 `@miint-sunny/dsh-nai-desk`，版本是 0.2.2，入口和预设各出现一次。不先卸载旧名而直接装新包，两份会并存，所以 README 要求先卸载旧名。
- 每次装完都看了 profile 的 `package.json` 和 `pnpm-workspace.yaml`：没有 `minimumReleaseAgeExclude`，也没有 `minimumReleaseAge` 的其他设置。
- 装好的包目录与归档逐字节相同，装上的 67 个技能文件逐个对上 `vendor.json`。
- 标签方式：装好的包目录里没有它自己的 `node_modules`，文件清单与 0.2.2 归档一致，`lib/` 三个文件与仓库逐字节相同，所以安装没有执行本插件的构建。这一项来源是本地 git 仓库，不是真的从 GitHub 下载。
