# 组件与兼容约定

## 术语

| 名称 | 本项目中的含义 |
|---|---|
| 预设 | dsh 的系统指令、工具和技能配置组合 |
| 技能 | 随包分发的提示词方法文档，由 vendor.json 标识来源版本 |
| 模型工具 | 供模型调用的结构化操作，如 desk_read |
| 草稿 | 按会话保存的提示词数据，不是聊天历史或生成任务 |
| 编辑器 | 右侧「提示词稿纸」界面及其客户端状态 |

## 组件职责

| 源码 | 职责 |
|---|---|
| `src/entry.js` | 包根入口；区分全局草稿服务与旧隔离配置 |
| `src/isolation.js` | 控制 NAI5 预设中全局工具和技能的可见性 |
| `src/host.js` | 挂载存储领域、共享服务及可选的 Connection 路由 |
| `src/desk.js` | 草稿校验、按会话写入队列、版本比较和更新通知 |
| `src/tools.js` / `src/tools-plugin.js` | 将草稿操作注册到 NAI5 预设作用域 |
| `src/host-api.js` | HTTP 请求解析、会话预设检查及错误映射 |
| `src/client-state.js` | 未提交编辑、版本冲突、请求生命周期和更新等待 |
| `src/panel.jsx` | 编辑器与用户操作 |

界面偏好（页签、折叠状态）保存在客户端 localStorage；草稿正文由宿主存储管理。客户端内存中的待保存文字不是持久备份。

## 保留安装标识的原因

仓库和展示名改为 NAI Desk，包标识仍为 `dsh-nai5-prompting`。dsh profile 的依赖、bundle 配置及既有用户覆盖可能引用该标识；保留它可减少升级所需的配置迁移。

预设 ID `nai5-prompting` 同样保留，用于延续会话关联。保留 ID 不表示自动把旧聊天回复转成草稿。

dsh 的客户端发现需要全局包根入口。全局条目使用 `{mode: desk}` 启动草稿服务；没有该 mode 的旧根入口配置仍按隔离配置解释。单独复用隔离逻辑可使用 `./isolation` 导出。

## 访问边界

模型工具从执行上下文取得会话 ID。HTTP API 接受显式 sessionId，由 Connection 校验调用方，再由插件检查目标预设。草稿服务本身是可信宿主扩展可调用的内部服务。

工具和技能的可见性限制不构成进程或文件权限沙箱。插件不替代 dsh 的授权策略，也不提供额外的多用户访问控制。

## 构建与版本

`lib/` 是随包分发的构建产物。React 由宿主提供，服务端依赖按构建配置打包。安装没有本插件的构建生命周期钩子；维护者在发布前运行构建和测试。

插件发布版本、HTTP 接口 v1 和 `schemaVersion: 1` 是三个独立标识。文案调整不应更改接口字段、错误码或存储格式；修改已发布包的文件时使用新发布版本，不重写已发布标签或同名附件。

具体协议与一致性限制见 [API 参考](api.md)。
